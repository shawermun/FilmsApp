В этом блоке я закрыл именно тот кусок, который логично делать следующим после карточки фильма:

1. **SearchScreen**
   - фильтр по типу контента: все / фильмы / сериалы;
   - сортировка по **новизне**;

   - поэтому фильтр по рейтингу и гибридный режим визуально понятнее;

## Как работает гибридный фильтр

Сценарий из твоего примера я сделал так:

- задаётся минимум рейтинга, по умолчанию **7.0**;
- задаётся окно новизны, по умолчанию **4 года**;
- сначала отбрасываются фильмы ниже порога;
- потом остаются только релизы внутри окна;
- внутри этого набора приоритет такой:
  1. более новый год;
  2. при равном годе — более высокий рейтинг.

То есть пример:

- 2024 — 6.9
- 2023 — 7.4
- 2020 — 7.6

результат будет **2023 / 7.4**, потому что 2024 ниже порога, а 2023 новее 2020.

## Что проверить после вставки

1. Поиск по названию всё ещё работает с debounce.
2. Очистка строки поиска возвращает экран к новинкам за 2 недели.
3. В режиме **По рейтингу** фильмы действительно переставляются по `vote_average`.
4. В режиме **Новый + достойный** выдача отсекает слабые по рейтингу релизы.
5. В режиме **Топ за период** диапазон `2010–2015` и `последние 4 года` реально меняет список.
6. Добавление фильма в библиотеку из поиска не показывает alert и меняет badge статуса.

## Замечание

Фильтры работают поверх того, что вернул TMDB в текущей выдаче. То есть это не серверный advanced search по всей базе TMDB, а **клиентская умная сортировка/фильтрация уже найденных результатов** — для текущей архитектуры это самый безопасный и быстрый шаг.
