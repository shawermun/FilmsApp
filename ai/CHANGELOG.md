## 2026-08-04 — Gemini: автоподбор модели через ListModels, честные ошибки вместо «Недостаточно данных»

**Проблема (от пользователя):** Модель `gemini-3.6-flash` использует токены (видно в AI Studio), но приложение долго «думает» и выдаёт ошибку. При переключении на `gemini-2.5-flash-lite` — «Недостаточно данных» при полностью заполненных полях.

**Причины:**
1. Модели `gemini-3.6-flash` не существует в API — вручную прописанная константа приводила к 404, а `fetchWithTimeout` маскировал причину под «Не удалось обратиться к AI-провайдеру».
2. Сообщение «Недостаточно данных» — это состояние экрана `hasLoaded=true` + пустой список: после неудачного запроса catch НЕ сбрасывал `hasLoaded`, поэтому вместо текста ошибки показывался заглушка «Недостаточно данных».
3. Таймаут 25 сек срабатывал как AbortError и маскировался под сетевую ошибку.

**Исправления в `src/api/recommendations.ts`:**
- **Автоподбор модели:** `resolveGeminiModel()` запрашивает `GET /v1beta/models?key=...`, фильтрует модели с `supportedGenerationMethods: generateContent` по паттерну `gemini-*-flash*` и выбирает лучшую по приоритету `gemini-3 → gemini-2.5 → gemini-2.0` (без lite). Результат кешируется в `resolvedGeminiModel`; при 404 кеш сбрасывается. В консоль выводится выбранная модель и полный список доступных.
- **Таймаут:** 25 сек → 90 сек (`AI_REQUEST_TIMEOUT_MS`), AbortError теперь даёт честное сообщение «превысил 90 сек», сетевая ошибка — отдельное сообщение.
- **Диагностика пустых ответов:** при пустом тексте извлекается `finishReason`/`promptFeedback.blockReason`; при SAFETY-блокировке — понятное сообщение «Переформулируйте предпочтения», иначе — причина в тексте ошибки. В консоль всегда пишется полный JSON ответа.

**Исправления в `src/screens/RecommendationsScreen.tsx`:**
- В catch обоих обработчиков добавлен сброс `setHasLoaded(false)`/`setHasGuessed(false)` — теперь при ошибке показывается красный блок с реальным текстом ошибки, а не «Недостаточно данных».
- Если ИИ вернул рекомендации, но TMDB не нашёл ни одного совпадения — отдельное сообщение с подсказкой проверить ключ TMDB.

**Проверка:** `npx tsc --noEmit` — 0 ошибок.

## 2026-08-04 — Исправления фильтров поиска: популярность, порог голосов, серверный «Топ за период»

**Исправлено 3 проблемы:**

1. **Режим «Обычный» теперь показывает самые популярные.** Сортировка по `popularity` из TMDB (в тип `TMDBSearchResult` добавлено поле `popularity`). Для новинок — самые популярные релизы за год, для поиска — самые популярные результаты.

2. **Бесконечная загрузка в «Топ за период» устранена.** Причина: фильтр применялся к «новинкам за год», а при выборе старых периодов (напр. 2010–2015) список пустел → `onEndReached` срабатывал бесконечно. Решение: режим «Топ за период» теперь загружает данные отдельным серверным запросом `getTopRatedForPeriod(startYear, endYear)` через `/discover` с диапазоном дат и `sort_by=vote_average.desc` — независимо от новинок. Добавлены состояния загрузки/ошибки с кнопкой «Повторить», защита от гонки запросов через requestId. Догрузка по скроллу (`onEndReached`) блокируется для всех активных фильтров.

3. **Отсев «фейковых 10 звёзд».** Во все рейтинговые режимы (`rating`, `hybrid`, `top_rated_period`) добавлен порог `vote_count >= 30` — фильмы с парой голосов больше не вытесняют нормальные. В `getTopRatedForPeriod` порог применяется на стороне сервера (`vote_count.gte=30`). В `buildFilterSummary` отображается пометка о пороге голосов.

**Изменённые файлы:**
- `src/types/index.ts` — поле `popularity` в `TMDBSearchResult`
- `src/utils/searchFilters.ts` — `MIN_VOTE_COUNT = 30`, `getVoteCount`, `getPopularity`, `byPopularity`, `hasUsableRating` с порогом голосов, `default` → сортировка по популярности, обновлены тексты summary
- `src/api/tmdb.ts` — новая функция `getTopRatedForPeriod` (discover по периоду лет, vote_count.gte=30, сортировка по рейтингу)
- `src/screens/SearchScreen.tsx` — состояния `periodResults/periodLoading/periodError`, useEffect загрузки топа за период с защитой от гонки, блокировка `onEndReached` при активном фильтре, отдельные экраны загрузки/ошибки для периода

**Проверка:** `npx tsc --noEmit` — 0 ошибок.

## 2026-08-04 — Фильтры поиска: новизна, отзывы, «свежий + топ», топ за период

**Новые возможности:**

Под вкладкой «Поиск» добавлена горизонтальная строка чипов-фильтров, применяющихся к любой выдаче (и к новинкам, и к результатам поиска по запросу):

1. **Обычный** — выдача TMDB как есть (по релевантности / дате).
2. **Сначала новые** (`newest`) — сортировка по дате релиза от новых к старым.
3. **По отзывам** (`rating`) — сортировка по рейтингу TMDB по убыванию, тайтлы без оценки скрываются.
4. **Свежий + топ** (`hybrid`) — гибрид новизны и оценки: приоритет у свежих релизов с высоким рейтингом. Настраиваемые параметры: «Оценка от» (по умолчанию 7) и «Окно новизны, лет» (по умолчанию 4). Тайтлы без рейтинга скрываются.
5. **Топ за период** (`top_rated_period`) — фильмы/сериалы с максимальной оценкой за выбранный диапазон лет (сортировка: рейтинг ↓, затем новизна ↓). Поля «Период с … по …» и быстрые пресеты: «Последние 4 года», «2020-е», «2010–2015», «2000-е».

Под чипами отображается поясняющий текст (`buildFilterSummary`) о текущем режиме.

**Изменённые файлы:**
- `src/screens/SearchScreen.tsx` — состояния фильтров (`sortMode`, вводы параметров), `filteredResults` через `applySearchFilters` (useMemo), UI: строка чипов, карточки параметров для hybrid/периода, пресеты периодов, новые стили
